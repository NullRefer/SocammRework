## 业务与设备隔离验证

使用仓库外的临时控制台验证器链接实际生产源文件，配合替身 IO/SFC、真实临时 SQLite 和本机 Modbus TCP 模拟端点，共 **43 项检查通过**。没有向仓库新增单元测试项目，没有连接真实 SFC、PLC、螺丝批或生产数据库。

- 上料：SFC 穴位映射、站点与 L/J 配对校验、未知位置、无效 JSON 和缺失 rc 拒绝；要求穴位写入主表。
- 拆螺丝扫码：八穴数组、产品码、更新标记和成功反馈顺序；不存在在线记录时失败。
- 曲线：两套地址关联、仅文件保存、不写 PLC 或主表、无法关联时保留 UNMATCHED 文件；历史文件恢复两把工具的最近曲线。
- 穴位结果：保存后才清零；无在线记录、非法穴位和保存失败不清零；完整要求集合逐穴判定。
- 下料：全要求穴位 OK 才调用 PASS；缺失、NG 或额外穴位不能替代所需结果；处理成功仅软删除主表；SFC 失败保留在线记录；未找到当前产品时不残留上个产品的 OK 展示。
- Runtime 与 IO：真实框架 Runtime 的扫码反馈在清零前；条码控制字符与长度校验；写入最多三次并保留根因；预取消不执行写入。
- Vanguard：真实 Modbus 数据包解析、末块采样、扭矩比例、结果字段、断开与同实例重连、重新配置保留订阅；框架设备目录和 keyed DI 可发现并解析 ITighteningDevice。

## SFC 模型按接口合并

依据《IPEBG_TW_SFC接口文档》的上料确认 GET_DEKIT_LOCATION、普通过站 STATION_RECORD，将 Models/SFC 精简为 LoadConfirm.cs 与 StationRecord.cs。每个文件包含对应请求、响应，移除公共基类与继承。字段保持 SN、RESULT、EMP、MACHINE_CODE、ERROR_CODE，以及各自 rc 和错误描述键；位置/站点解析、必填 rc、屏蔽分支和过站业务保持原有处理。

本次合并后，构建（0 错误，既有依赖审计告警仍在）、whitespace 和 diff 检查通过。静态核对确认目录仅两个文件、四个无继承模型，字段与接口文档一致，旧模型引用已移除。

## 交互逻辑移回 Flow

移除 ILoadService、IScrewService、IUnloadService 及对应实现，原交互方法分别移到 LDFlow、ScrewFlowBase、UldFlow 内部。各 Flow 直接注入 IO、SFC、产品数据、曲线与展示状态等所需基础能力；两台拆螺丝机继续共用 ScrewFlowBase。

本轮仅调整代码归属：五个交互方法的主体与移动前逐一核对一致，仅访问级别由 public 改为 private；轮询入口改为调用本类方法。PLC 地址、清零时机、SFC/持久化顺序、曲线订阅与退订均保持原样。解决方案构建（0 错误，既有依赖审计告警仍在）、whitespace 与 diff 检查通过。本轮未重复执行原先的 43 项隔离冒烟，也未进行现场设备联调。
